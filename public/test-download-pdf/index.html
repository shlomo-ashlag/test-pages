ABS-5434 Firefox Downloads

PDF from a script URL

Some sites send a PDF from a script, for example show_temp.pl?file=report.pdf. With the extension in Firefox such a file was saved as show_temp.pl. After the fix the extension gets the file type from the Content-Type header, like Chrome does, so the file is saved as show_temp.pdf.

This test is for Firefox. Other browsers name the file themselves, so the result here says nothing about the fix.

Before you start

  1. Open this page in Firefox with the extension build you want to check.
  2. The flag enableInlineFileScanInFirefox must be on. If a PDF opens in a tab instead of downloading, the scan is off.
  3. Watch the file names in the Firefox downloads panel (the arrow button in the toolbar).
  4. To see the bug itself, do the same on a build without the fix, for example 1.149.14.
  5. Every case also checks what the server sends. If a check is red, the site is not set up right and that case proves nothing.

Fixed by ABS-5434

The fix changes these names.

1

Script URL with a query

cgi-bin/show_temp.pl?file=6006422-0--14206.pdf&type=application/pdf

This is the case from the ticket. The URL has a query, so .pl is the script that sends the file, not the file type. The name gets .pdf from Content-Type.

Server sends
Content-Type: application/pdfno Content-Disposition
Expected name
show_temp.pdf
Without the fix
show_temp.pl

URL without an extension

documents/6006422

The last part of the URL has no extension, so the name gets .pdf from Content-Type.

6006422.pdf
